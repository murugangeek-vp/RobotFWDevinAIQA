BANK MIGRATION VALIDATION (source bank → target bank)

Goal: prove to the customer that 100% of in-scope core-banking data migrated
correctly — every record, every column, every transformation — with an audit
trail. Work through this checklist; do not sign off on partial evidence.
Reference env: `config/environments/webster_santander.yaml`
(Webster Postgres → Santander Snowflake, `fake: true` locally).

## 1. Environment & credentials

- Confirm the env YAML: `source` block (source-bank adapter + connection,
  RO credentials only — verification must never write to the source bank) and
  `target` block (`type`, `${VAR}` refs, `mapping_workbook` path).
- Production runs are verify-only: `RECON_SKIP_LOAD=true` — the bank's ETL
  loaded the target; we only validate. Never run loader mode against a
  bank-loaded target.

## 2. Mapping & scope

- The mapping workbook (`data/mapping/bank_mapping.xlsx`, generated by
  `scripts/generate_mapping_workbook.py`, parsed by `libs/mapping/`) defines
  entity/table/column mappings source→target. Verify every in-scope entity is
  mapped — no silent unmapped tables.
- Business rules workbook (`data/rules/business_rules.xlsx`) covers the
  transformation/data-quality contract.
- Declared scope (`row_filter`, WHERE clauses) must match the migration spec
  exactly — e.g. active accounts only. Out-of-scope rows in target =
  `extra_in_target` defects, not noise.

## 3. Execution layers (all must pass)

1. Source extract sanity — header/metadata/shape per contract.
2. Source data-quality — contract rules + workbook rules.
3. Target schema — columns/types/nullability/keys vs contract (drift = fail).
4. Record comparison — row counts, missing keys, extra keys, per-column diffs.
5. Transformations — every derivation recomputed and matched.
6. Excel rules — zero violations at HIGH/MEDIUM/CRITICAL.
7. Run: `robot --exclude requires_write -d results -v ENV_FILE:<env>.yaml tests/pilot`

## 4. Evidence & sign-off

- Artifacts: `results/report.html`, `log.html`, `run_summary.json`,
  `business_rules_summary.xlsx` (Run Info sheet = audit record: timestamp,
  environment, contract version, executor, commit, verdict).
- Sign-off requires: expected vs actual counts equal for EVERY entity, zero
  missing/extra keys, zero column diffs, zero failing-severity violations.
- Any mismatch: report entity, key(s), column, expected vs actual — never
  "data looks fine". One wrong balance fails the migration.
- Results contain compared data — treat artifacts as sensitive (git-ignored);
  share only through approved channels.

## 5. Escalate, don't improvise

Ask before: running against a production-like endpoint, any write to a bank
database, extending verification beyond declared scope, or handling data that
might be real customer data.
